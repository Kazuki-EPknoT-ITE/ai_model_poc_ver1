# 部門代表による試用の手順書とアンケート（T-55）

> POC の合格条件 9.2-4「利用者代表（各部門1名程度）の試用で『業務で使いたい』という評価が過半数」を判定するための手順。
> 対象: 試用者（各部門の代表）と、準備・集計をする IT 担当。時期は PHASE 2（2027年3月）を想定する。

---

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 試用者 | 各部門1名程度（目安 6〜8名）。普段から Excel・Word・PDF を扱う人 |
| 期間 | 1人あたり5営業日。初日に30分の説明会、最終日にアンケート |
| 環境 | 検証機（RTX 5080）の Gateway。モデルは 12B（POC で評価中の版。モデル台帳の ID を記録する） |
| 端末 | 試用者の業務 PC（Windows 11）にインストーラで導入する |
| 判定 | アンケートの設問 Q1「業務で使いたい」に「使いたい」「どちらかといえば使いたい」と答えた人が**過半数**なら合格 |

## 2. 事前準備（IT 担当）

1. **アカウント**: 管理画面（`https://<サーバー>/admin/`）の「利用者」で試用者を追加する。権限は「利用者」、ネットの上限は「オフ」。初期パスワードは個別に手渡しし、初回に変えてもらう。
2. **配布物**: インストーラ（`LocalLLMAgent-Setup-<版>.exe`）を社内共有に置く。サーバーの URL（と予備機の URL）を案内文に書く。
3. **共通指示**: 管理画面の「共通指示」に、社内の表記ルール（金額は税込、和暦か西暦か など）を入れて配信する。
4. **機密語辞書**: 船名・取引先などを登録しておく（ネットはオフだが、誤ってオンにした場合に備える）。
5. **監視**: ダッシュボードで待ち件数と GPU 温度を見られるようにする。試用期間中は1日2回確認する。
6. **記録の準備**: 第5節の「試用記録シート」を試用者ごとに用意する（Excel、社内共有）。
7. **バックアップ**: 試用者には、作業フォルダに**コピーしたファイル**を使ってもらう（元のファイルを直接使わない）。

## 3. 説明会（30分）

1. 何をするアプリか（5分）: 「頼んだ作業を、AI がパソコン上で手順に分けて進める。ファイルは社内のサーバーだけで処理し、外部に送らない」。
2. 使い方の実演（15分）: 第4節の課題 A を画面で見せる。
   - 作業フォルダの選び方。依頼の書き方（「何を」「どのファイルから」「どこに」）。
   - 進み具合の見方（手順カード）。承認の求めに応えるところ。
   - 結果の確認と「元に戻す」。
3. 注意（10分）:
   - **結果は必ず人が確認する**。金額・日付・取引先名は特に。AI の結果に「要確認」と出たものは原本と照らす。
   - 作業フォルダの外のファイルを触るとき、削除・移動するときは承認を求められる。内容を読んでから承認する。
   - 個人情報・社外秘の扱いは普段の社内ルールと同じ。
   - 困ったら「停止」を押してよい。途中までの変更は「元に戻す」で戻せる。

## 4. 試用の課題

毎日1つ以上を行い、第5節のシートに記録する。課題 A〜C は全員、D は部門の業務から自由に選ぶ。

| 課題 | 依頼の例 | 用意するもの | 確認すること |
| --- | --- | --- | --- |
| A 請求書→Excel 転記 | 「請求書フォルダの PDF を読んで、送金明細を Excel にまとめて。列は 請求日・請求元・船名・通貨・金額」 | 請求書の PDF 10〜20件（コピー） | 金額・日付・請求元が原本と合うか。読めなかった請求書が「失敗」として理由付きで挙がるか |
| B 契約書の要約 | 「この傭船契約書を読んで、当事者・期間・料金・解約条件を1ページにまとめて Word にして」 | 契約書の docx／PDF 1〜2本 | 要約の正しさ。条項の参照（何条か）が合っているか |
| C Word で文書作成 | 「9月の入渠報告書を Word で作って。船名は○○、費用の精算時期も書いて」 | 過去の報告書（書式の見本） | 書式が崩れていないか。社内の表記ルールどおりか |
| D 自由課題 | 部門の定型作業（集計・照合・文書の整形など） | 普段使っているファイル（コピー） | 普段の作業時間との比較 |

## 5. 試用記録シート（1作業1行）

| 列 | 記入内容 |
| --- | --- |
| 日付・課題 | A〜D と、依頼の文（そのまま貼る） |
| 結果 | 完了／途中で止めた／失敗 |
| かかった時間 | AI が完了するまでの時間（分）と、確認・手直しにかかった時間（分） |
| 普段の時間 | 同じ作業を手で行う場合の目安（分） |
| 手直し | 直した箇所の数と内容（例: 金額の桁、取引先名の表記） |
| 承認 | 承認を求められた回数と、内容がわかりやすかったか（○／△／×） |
| ひとこと | 良かった点・困った点 |

自動で残るもの（試用者の記入は不要）: 監査ログ（誰が・いつ・どのファイルを操作したか）、手順数、待ち時間。IT 担当が管理画面の「監査ログ」から CSV で出し、シートと突き合わせる。

## 6. アンケート（最終日）

5段階の設問は「1: まったくそう思わない 〜 5: とてもそう思う」。

| No | 設問 | 形式 |
| --- | --- | --- |
| **Q1** | **このアプリを業務で使いたいですか**（使いたい／どちらかといえば使いたい／どちらかといえば使いたくない／使いたくない） | 4択（**判定に使う**） |
| Q2 | 頼んだ作業が、期待どおりに完了した | 5段階 |
| Q3 | 結果の確認・手直しを含めても、手で行うより早かった | 5段階 |
| Q4 | 進み具合（手順カード）がわかりやすかった | 5段階 |
| Q5 | 承認の求めは、内容がわかりやすく、多すぎなかった | 5段階 |
| Q6 | 応答の速さに不満はなかった | 5段階 |
| Q7 | 情報の扱い（社外に出ない・元に戻せる）に安心できた | 5段階 |
| Q8 | 最も役に立った作業は何ですか | 自由記述 |
| Q9 | 使いにくかった点・直してほしい点 | 自由記述 |
| Q10 | ほかに任せたい作業があれば | 自由記述 |

## 7. 集計と判定（IT 担当）

1. Q1 で「使いたい」「どちらかといえば使いたい」の人数 ÷ 回答者数 を出す。**0.5 を超えれば 9.2-4 は合格**。
2. 補助の材料として、課題ごとの完了率、手直しの件数、時間の短縮（普段の時間 −（AI の時間＋確認の時間））を集計する。課題 A は評価セット invoice_extraction の結果と並べる。
3. Q9・Q10 は機能要望として一覧にし、`local_llm_impl_plan.md` の T-66（Should/Could の残り）の優先順位づけに使う。
4. 結果は「試用報告書」（1〜2ページ）にまとめ、POC 合格判定（2027年3月末）の資料にする。モデル台帳の ID・アプリの版・期間・参加者数（部門名のみ。氏名は書かない）を必ず記載する。

## 8. 試用中の問い合わせ

| 困りごと | 対応 |
| --- | --- |
| ログインできない | 管理画面でアカウントの状態を確認し、パスワードを再設定する |
| 「予備機で接続中」と出た | 本番（検証）機に繋がっていない。ダッシュボードとサーバーを確認する（作業は予備機で続く） |
| 作業が長く終わらない | 画面の手順カードで止まっている所を確認。「停止」→ 依頼を短く分けて頼み直す |
| 結果がおかしい | 「元に戻す」で戻し、依頼の文と結果を記録シートに残して IT 担当に連絡する |
