# ADR-006: OCR はサーバーの GPU で処理する

- 状態: 承認済み（2026-10-11。設計提案 R8 の採用をユーザーが承認）

## 背景
スキャンPDF・FAX の日本語OCR（PDF-03）が必要だが、クライアントPCは GPU なし・メモリ8GB を前提としており、手元で高精度なOCRを動かすと遅い。Gemma 4 の画像入力もサーバーにしかない。

## 決定
- 推論サーバー上に「画像読取サービス」（`server/ocr`）を置き、OCR エンジンと Gemma 4 の画像入力を使えるようにする。
- クライアントはテキストのないページを 200dpi の PNG にして、TLS で `/v1/vision/ocr` に送る。サーバーは処理が終わったら破棄し、保存しない。
- OCR エンジンは PaddleOCR（Apache-2.0）を第一候補とし、YomiToku（商用ライセンスが必要）と Gemma 4 の画像入力を、POC の帳票抽出評価セットで比べて決める。

## 検討した代替案
- **クライアントの CPU で OCR**: 社外に出ない点は同じだが、遅く、PRF-06（請求書10枚を5分以内）を満たしにくい。
- **クラウドの OCR**: 機密情報が社外に出るため不可。

## 影響・リスク
- 「ファイル操作は各PC」の原則の例外になる（ページ画像は社内LANの中だけを通る）→ 要件書 v0.3 に明記する。
- GPU の負荷が増える → OCR もキューに入れ、推論と同じく公平スケジューリングの対象にする。
- 監査ログにはファイル名とページ数だけを残す。
