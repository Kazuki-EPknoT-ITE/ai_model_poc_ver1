# ADR-003: Gateway は FastAPI＋PostgreSQL で自作する

- 状態: 承認済み（2026-10-11）

## 背景
要件書 4.2 では「LiteLLM 等または自作」としていた。待ち行列をサーバー再起動後も保持すること（RUN-09）、手順単位の公平スケジューリング（RUN-10）、冪等キーと SSE の再開、利用者ごとの同時実行数の上限（ADM-04）が必要になる。

## 決定
- Python 3.12＋FastAPI で Gateway を自作し、PostgreSQL 16 に利用者・ジョブ・監査・台帳を置く。
- `/v1/steps` は `Idempotency-Key` を必須にし、SSE は `Last-Event-ID` で途中から再開できるようにする。
- 利用者ごとのキューを手順単位で順番に回し、短い依頼を優先する。
- 推論は vLLM の OpenAI 互換 API を内部から呼ぶ。

## 検討した代替案
- **LiteLLM Proxy＋Redis**: ルーティングと鍵管理はあるが、永続キュー・手順単位の公平性・ジョブ単位の SSE 再開がないため、結局は自作部分が大きくなる。
- **キューを持たない（クライアントが再投入する）**: RUN-09 を満たせず、順番待ちの公平性も保てない。

## 影響・リスク
- 保守するコードが増える → API 仕様（`local_llm_api.md`）と自動テストで品質を担保する。
- PostgreSQL の運用（バックアップ）が必要 → OPS-04 で夜間に NAS へバックアップする。
