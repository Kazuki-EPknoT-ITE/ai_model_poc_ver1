# ADR-007: キューに依頼本文を暗号化して完了まで置く

- 状態: 承認済み（2026-10-11。設計提案 R4 の採用をユーザーが承認）

## 背景
SEC-06（サーバーに会話本文を既定で保存しない）と RUN-09（待ち行列と実行中の依頼をサーバー再起動後も保持する）が衝突する。待ち行列を残すには、依頼の中身をどこかに置く必要がある。

## 決定
- ジョブの本文（プロンプト）は AES-256-GCM で暗号化して PostgreSQL の `job_payloads` に置き、ジョブが完了・取り消しになったら直ちに削除する。
- 応答は、クライアントの再接続用に暗号化して最大10分だけ残し、その後は削除する。
- 暗号鍵はサーバーの鍵ファイル（root のみ読み取り可、DB とは別の場所）に置き、定期的に更新する。
- ログ・メトリクスに本文を出力しない。
- この運用を SEC-06 の例外として要件書 v0.3 に明記する。

## 検討した代替案
- **キューを持たず、クライアントが再投入する**: 本文はサーバーに残らないが、再起動で順番が失われ、RUN-09 を満たせない。
- **平文で一時保存**: 鍵管理は不要だが、DB のバックアップに本文が残る危険がある。

## 影響・リスク
- DB のバックアップに暗号化された本文が入りうる → 完了済みのものはバックアップの時点で削除されている。未完了分も鍵がなければ読めない。
- 鍵を失うと再起動時に未完了のジョブを戻せない → その場合はクライアントの冪等な再投入で復旧する（状態の正本はクライアント）。

## 関連要件ID
RUN-09, SEC-06, SEC-02, OPS-02
