# ADR-008: 認証は独自アカウントから始め、OIDC を後から追加できるようにする

- 状態: 承認済み（2026-10-11。ユーザーが「独自アカウントで始める」を選択）

## 背景
ADM-01 で利用者ごとのログインが必要だが、Microsoft 365 / Active Directory と連携するかは確認事項（要件書 11.2）のまま。POC を待たせないよう、まず単独で動く方式が必要になる。

## 決定
- Gateway に独自アカウント（利用者ID＋パスワード）を持たせ、管理画面で登録・無効化・パスワード再設定を行う。
- パスワードは **argon2id** でハッシュ化する。ログインの試行回数を制限し、5回続けて失敗したら15分ロックする。
- トークン: **アクセストークン15分**（JWT。署名は EdDSA）、**リフレッシュトークン30日**（不透明な値で、DB にはハッシュだけを保存する。使ったら新しいものに交換し、再利用を検知したら一連のトークンをすべて失効させる）。
- クライアントはリフレッシュトークンを `safeStorage`（DPAPI）で保存する。
- 認証は `AuthProvider` インターフェース（`authenticate`, `resolve_groups`）で抽象化し、**後から OIDC（Entra ID）や LDAP を追加**できる構造にする。部門・役職（ADM-02 の権限）は、プロバイダが返すグループを Gateway 内の権限グループに対応させる。

## 検討した代替案
- **最初から Entra ID（OIDC）**: パスワード管理が不要になるが、テナントの設定と社内の調整が POC 前に必要になる。
- **オンプレ AD（LDAP/Kerberos）**: 社内環境への依存が大きく、検証機単体で開発しにくい。

## 影響・リスク
- パスワードの管理（初期パスワードの配布・再設定）の運用が必要になる。
- 将来の連携時に利用者IDの対応付けが必要 → `users.external_id` 列を最初から用意しておく。
