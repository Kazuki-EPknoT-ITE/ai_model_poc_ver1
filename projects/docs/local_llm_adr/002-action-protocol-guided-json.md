# ADR-002: 独自のアクションプロトコルを guided_json で強制する

- 状態: 承認済み（2026-10-11）

## 背景
小さいモデル（Gemma 4 12B）でエージェントを成立させるには、ツール呼び出しの形式崩れをなくす必要がある（RUN-04, AGT-05）。vLLM のモデル固有のツールパーサーは、モデルや版ごとに挙動が異なる。

## 決定
- モデルの1手を `tool_call` / `plan_update` / `ask_user` / `final` の JSON に固定する（`local_llm_protocol.md` §1）。
- vLLM の `guided_json`（xgrammar）で、その時点で使えるツールの oneOf 文法を毎手作って強制する。
- 1回の応答で返すアクションは1つだけとし、並列の処理は `batch.run` に任せる。
- 学習データ（`ml/datagen`）もこの形式で作り、`protocol_version` を記録する。

## 検討した代替案
- **vLLM のツールパーサー（OpenAI 互換の tools）**: 標準的だが Gemma の版に依存し、崩れた出力が生まれうる。
- **自由テキスト＋後から構文解析**: 失敗率が高く、再試行で GPU を無駄にする。

## 影響・リスク
- 文法のコンパイルにかかる時間 → ツール集合のハッシュでキャッシュする。
- 制約付き生成で精度が下がる可能性 → POC の評価セットで、制約なしの場合と比較する。
- プロトコルを変えると学習データの作り直しが必要になる → 版を管理する。
