# ロールバック（復元）の仕組み — agency-agents

開発中に「機能やデザインを追加したが元に戻したい」「ある時点まで戻したい」と
なったときに、**実装（コード）とログを一緒に**その時点へ戻すための仕組み。

## 考え方：チェックポイント = 復元ポイント

- **実装のまとまりごとに「チェックポイント」を作る**（= git コミット1つ）。
  コミットには**コード＋ `ref/LOG.md` の両方**が含まれるので、戻せば両方戻る。
- チェックポイントは**ローカルのみ**（GitHub には自動 push しない）。
  安定した時点で明示的に push する。
- **ロールバックは必ずバックアップを自動保存してから実行**するので、
  戻したあとに「やっぱり戻す前に戻したい」も `--undo` で可能。**何も失われない。**

## 使い方

### 1. 復元ポイントを作る（実装後に自動で実行される）
```bash
scripts/checkpoint.sh "追加した機能やデザインの要約"
```

### 2. 戻れる時点の一覧を見る
```bash
scripts/rollback.sh --list
```
```
== Restore points (newest first) ==
b6897f2 (HEAD -> main) checkpoint: restyle Y      ← 最新
4bf7590 checkpoint: add feature X
2e16864 checkpoint: base
```

### 3. 直前の実装を元に戻す
```bash
scripts/rollback.sh --last
```
→ コードも `ref/LOG.md` も1つ前のチェックポイントに戻る。

### 4. 特定の時点まで戻す
一覧の左端のID（例 `4bf7590`）を指定:
```bash
scripts/rollback.sh 4bf7590
```

### 5. ロールバックを取り消す（戻しすぎたとき）
```bash
scripts/rollback.sh --undo
```
→ 直前のロールバック前の状態（自動保存されたバックアップ）に復帰。

## 安全設計

- ロールバック前に `backup/<日時>` タグへ現在の状態を退避（`--undo` で復帰可能）。
- **未コミットの変更があるとロールバックは中断**する（うっかり消さないため）。
  先に `scripts/checkpoint.sh "wip"` で保存するか `git restore .` で破棄する。
- ロールバックはローカル履歴を書き換える。**すでに push 済みの時点より前に戻す**
  場合は、次回 push で force が必要になるため、実行前に必ず確認する。

## 実装後の確認（このプロジェクトの運用）

実装が終わると、担当（Claude）は毎回チェックポイントを作ったうえで、
**「このまま進める／直前の実装を元に戻す／特定の時点まで戻す」**をあなたに確認する
（`CLAUDE.md` の実装後プロトコル参照）。「戻す」を選べば上記コマンドで復元する。
