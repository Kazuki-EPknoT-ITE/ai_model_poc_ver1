# プロジェクトルール — agency-agents

> このファイルはプロジェクトの「守るべきルール・制約・方針」の唯一の正本。
> 変更したら `ref/LOG.md` にその旨を記録すること。
> （中身は必要に応じて自由に編集してよい。以下は初期テンプレート。）

最終更新: 2026-07-24

---

## 1. 基本方針

- このリポジトリは **AI エージェント定義（Markdown）のカタログ**。
  コードよりも「エージェント定義ファイルの品質・一貫性」を最優先する。
- 破壊的・不可逆な操作（大量削除、既存エージェントの一括改変、push/force など）は
  実行前に必ずユーザーへ確認する。
- 不明点は推測で進めず、選択肢を提示して確認する。

## 2. エージェント定義ファイルの規約

- 1ファイル = 1エージェント。配置は該当部門ディレクトリ直下
  （例: `engineering/engineering-frontend-developer.md`）。
- 先頭に YAML frontmatter を持つこと。最低限のキー:
  - `name`, `description`（他に `color`, `emoji`, `vibe` など既存に倣う）
- 新規部門を追加する場合は `divisions.json` にも登録し、
  `scripts/check-divisions.sh` を通すこと。
- 変更後は該当チェックを実行して整合性を確認する:
  - `scripts/lint-agents.sh` / `scripts/check-divisions.sh` / `scripts/check-tools.sh`

## 3. コーディング / 編集スタイル

- 既存ファイルの書式・トーン・見出し構成に合わせる（独自様式を持ち込まない）。
- `integrations/` 配下は `scripts/convert.sh` の **出力（生成物）**。
  手で直接編集せず、ソース（各部門の `.md`）を直してから再生成する。

## 4. 作業の進め方

- セッション開始時は `CLAUDE.md` の「セッション開始プロトコル」に従う。
- 作業の区切りごとに `ref/LOG.md` へ追記する。
- 大きめの作業は事前に段取りを共有してから着手する。
- **実装が終わったら毎回、チェックポイント（復元ポイント）を作成**し、ユーザーに
  「このまま進める／元に戻す」を確認する（`CLAUDE.md` 実装後プロトコル手順3〜4）。

## 6. ロールバック（復元）

- 復元ポイント作成: `scripts/checkpoint.sh "<要約>"`（コード＋ログを1コミット）。
- 復元: `scripts/rollback.sh --list|--last|<時点ID>`、取り消し: `--undo`。
- **バックアップ自動保存**・未コミット変更はブロック・**push済みより前へ戻す時は要確認**。
- 詳細は `ref/ROLLBACK.md`。

## 5. 環境

- OS: Windows 11 / 既定シェル PowerShell。POSIX スクリプトは Bash ツールで実行。
- 一時ファイルは scratchpad を使い、リポジトリを汚さない。
