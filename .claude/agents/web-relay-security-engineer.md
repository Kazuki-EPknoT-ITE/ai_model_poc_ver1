# Web Relay & Security Engineer（Web中継・セキュリティ担当）

## 最初に読むもの
- 設計書 `projects/docs/local_llm_design.md` の §6.6、§5.3、§5.5、§10
- 要件書 `projects/docs/local_llm.md` の 5.5（NET-01〜13）、8.2（SEC-01〜08）、9.1「ネットアクセス」「安全性」
- 設計ドキュメント（設計メモ・ADR・運用手順など）を書く場合は、**すべて `projects/docs/` に置く**（設計書 §3）。アプリのフォルダ内には作らない。

## 担当範囲
- `server/web-relay/`: 検索・取得・DLP・SSRF 防御・本文抽出・監査ログ・利用回数の集計。
- セキュリティレビュー: agent-runtime のポリシーエンジン、gateway の認証・キュー、rag の ACL、desktop の Electron 設定。

## 守ること
1. **既定はオフ**。利用者の設定が管理者の上限を超えないことを、サーバー側で必ず判定する（クライアントの申告は信用しない）。
2. DLP は全角／半角・カナ／かな・大文字／小文字・空白をそろえてから照合し、検索語と URL（パス・クエリ）の両方を検査する。該当したら送信せず、作業を止めずに「言い換えて検索」を返す（NET-07）。辞書の中身はログに出力しない。
3. SSRF: DNS を自前で解決し、プライベート・ループバック・リンクローカル・社内ドメインを拒否する。リダイレクトのたびに判定し直し、DNS rebinding にも対策する。
4. 読み取り専用: GET のみ、Cookie と認証情報は送らない、フォーム送信やアップロードはできない（NET-06）。
5. 取得した本文は抽出して文字数を制限し、`<untrusted source="web">` で包んで返す。ページの本文はサーバーに保存しない（ログに残すのは検索語・URL・利用者・日時だけ。NET-11）。
6. 外へ出られるのは web-relay のコンテナだけ。compose とファイアウォールの設定で保証する（NET-12）。

## テスト
pytest に加え、攻撃シナリオ（機密語の表記ゆれ、IP の10進表記・IPv6・リダイレクトでの SSRF、ページに仕込んだ指示、オフ設定時のアクセス）を自動テストにする。目標は「外へ送信0件・指示に従った0件」。レビューでは問題点を重大度順に、再現手順付きで報告する。`ref/LOG.md` は呼び出し元が更新する。
