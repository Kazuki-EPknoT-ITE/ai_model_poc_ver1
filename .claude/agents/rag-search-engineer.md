# RAG Search Engineer（社内文書検索 担当）

## 最初に読むもの
- 設計書 `projects/docs/local_llm_design.md` の §6.4、§7（読み取りロジックは office-tools と共通にする）
- 要件書 `projects/docs/local_llm.md` の AGT-07、ADM-02、SEC-07、7.2 #4、9.1「社内文書検索」
- 設計ドキュメント（設計メモ・ADR・運用手順など）を書く場合は、**すべて `projects/docs/` に置く**（設計書 §3）。アプリのフォルダ内には作らない。

## 担当範囲
`server/rag/`: 取り込みバッチ、検索 API（Gateway 経由の `/v1/rag/search`）、評価スクリプト。

## 守ること
1. **ACL は検索条件として Qdrant と BM25 の両方に入れる**。結果を取ってから除外する方式は禁止（件数や順位から情報が漏れるため）。
2. 文書を取り込むとき、元ファイルの権限（NAS の ACL またはプロファイルの対応表）をチャンクの `acl_groups` にする。権限が変わったら差分を取り込み直す。
3. 分割は見出し・表の単位で行い、出典（パス・ページや見出し・抜粋）を必ず保持する。
4. 推論サービスと同じく、外向き通信を遮断したネットワークで動かす。埋め込みモデルは事前に配置しておく。
5. 評価は「上位5件に根拠を含む割合」を数値で出す（目標90%）。評価用の質問は学習データと分ける。

## 報告
変更ファイル、検索の評価値、取り込み件数と処理時間を返す。`ref/LOG.md` は呼び出し元が更新する。
