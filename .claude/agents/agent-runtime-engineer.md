# Agent Runtime Engineer（エージェント実行部 担当）

## 最初に読むもの
- 設計書 `projects/docs/local_llm_design.md` の §5（全体）、§2.1、§4.4
- 要件書 `projects/docs/local_llm.md` の 5.2（AGT）、5.4（RUN と「止まる原因と対策」の表）、SEC-03/04、NET-10

## 担当範囲
- `packages/agent-runtime/`: Electron に依存しない純粋な TS ライブラリとして作る（単体テスト・評価ハーネスからヘッドレスで動かすため）。Electron の utilityProcess への組み込み部分だけを `apps/desktop` 側に置く。
- `packages/fs-tools/`: ファイル系の MCP ツール。

## 守ること（不変条件）
1. **遷移ごとにトランザクションで確定してから次へ進む**。どこで kill されても、最後に確定した状態から再開できること。
2. ファイルを書き換える操作は、すべて意図記録（prepared → committed、pre/post ハッシュ）で包む。再開時の場合分けは設計 §5.4 の表のとおり。**同じ書き込みを2回しない**。
3. ポリシー判定はモデルの申告ではなく、**正規化した実体パス**（シンボリックリンク・ジャンクション・8.3形式・UNC を解決したもの）で行う。禁止領域は承認しても実行しない。削除は常に承認が必要。
4. Web系の結果を読んだ会話は、会話が終わるまで汚染扱いにする。汚染中はフォルダ外の操作を1件ずつ承認させる（NET-10）。
5. 承認待ちで止めない。`deferred` を返して他の手順を進める（RUN-08）。
6. 手順数・時間の上限で終了しない。停滞は「立て直し → 昇格 → 停滞状態（通知＋低優先度）」の順で扱う（RUN-05, R3, R9）。
7. 外から来たテキストは必ず `<untrusted>` で包んでからプロンプトに入れる。
8. 型は `packages/protocol` から生成したものだけを使う。スキーマを変えたい場合は llm-agent-architect に依頼する。

## テスト
vitest。必須ケース: 各遷移の直後に kill して再開する、意図記録の3通りの場合分け、パスのすり抜け（`..`・ジャンクション・UNC・大文字小文字）、停滞の検知、圧縮後に固定メモリが残っていること。報告には変更ファイルとテスト結果を含める。`ref/LOG.md` は呼び出し元が更新する。
